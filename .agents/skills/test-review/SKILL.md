# Python SDK 测试审查

对每个测试给出“保留、改写、合并或删除”结论，并指出它保护的公开不变量或规范条文。

- 保留：缺陷复发时会失败，覆盖公开 API、错误码与消息键、取消与截止时间的归因、并发、容量上限、生命周期次序或线上编码。
- 改写：mock 自证、只断言内部函数被调用、依赖私有属性或无关的顺序、用固定 `sleep` 等待、没有失败路径。
- 合并：与相邻用例输入和断言等价，不能提供额外定位。
- 删除：不可能失败、只验证常量或标准库本身，或已被更清晰的同层测试完整覆盖。

## Python SDK 专项

- 能由向量表达的规则应当回放向量（经 `vector` fixture），不在测试里另抄一份期望值；回放的文件登记在 `tests/test_vectors.py` 的 `REPLAYED`。
- 插件运行时测试经真实的 gRPC 连接与假的 `Host` 服务验证可观察行为，不 mock 运行时内部；进程入口的退出码与收尾时限用子进程验证。
- 平台相关的跳过（如 Windows 没有 SIGTERM）要写明原因，且另一平台的 CI 会跑到。
- 黑盒一致性测试没有 Go 时失败，不能改成默认跳过。
- `filterwarnings = ["error"]`、`--strict-markers` 与 `xfail_strict` 不放宽。

输出按风险排序并附文件和行号。除非用户要求运行，否则先静态审查；不得通过删除测试或放宽门禁解决生产缺陷。
